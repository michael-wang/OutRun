# OutRun Scene Studio｜極速漫遊・場景工作室

**狀態：需求方向已由 Michael 於 2026-11-23 明確提出；以下為設計／技術方案，尚未實作、未經遊戲或 Pixel 8 驗收。**

## 1. 產品目標

參考 Michael 提供的「街構 STREETFORM」三張介面截圖（真實材質／白模／線框；單棟建築亮綠外框、側欄參數、可自由移動鏡頭）。圖片留於對話，不因本規格自動公開到 Git。

**一句話：** 開啟任意一段《極速漫遊》賽道，在「真正的遊戲場景」裡自由瀏覽、點選物件、調整可理解的參數、比較美術／白模／線框，然後確認並**將結果寫回本地可版本化的 Stage 來源資料**，重開仍一致，最後直接試駕。

這不是另一個可觀賞的獨立 Demo，也不是把每段路切成互不相干的三維檔案。道路、物理、Worker、Ultra Water、賽事仍由既有正式遊戲系統維持唯一權威。

**美術順序：** 先找到值得追求的高品質 PC LookDev 上限，再以實際 Pixel 8 量測、LOD、貼圖壓縮、材質與陰影烘焙逐步接近 30 FPS；不將初期 FPS 預算當成藝術品質的先驗天花板。但 PC LookDev 仍須使用能轉移到 Three.js 的幾何、材質與場景資料，不能只輸出一張不可玩圖。

## 2. 使用者主流程

1. 在本地開發版進入「場景工作室」，選擇第一關、章節／景點，或自訂一個 100–500 m 左右的觀察範圍（不是限制場景只能 500 m）。
2. 直接呈現該範圍的**真實 Three.js／Ultra Water／夕陽**場景，等待道路與附近景物載入完成，顯示狀態。
3. 用滑鼠自由旋轉、平移、縮放；選擇「正常追車」、「道路前望」、「空拍」、「自由鏡頭」預設。顯示路線範圍與精確里程。
4. 切換 **實景（PBR）／白模（Clay）／線框（Wire）**。模式只改觀察呈現，不破壞來源材質／遊戲設定；保留選取輪廓與選取物件識別。
5. 點選路面、地形／岩岸、樹木群、房舍、場景組件等，顯示清楚的選取邊框與**此類資產真正有用的**參數。不可編輯的物件顯示來源與原因，絕不提供不生效的假滑桿。
6. 修改參數，獲得**真正的現場預覽**。輕量參數立即更新；重建網格、海岸遮罩、Worker Chunk 等需離線／昂貴步驟時，明示「重新生成」和進度，完成之前不冒充成功。
7. 使用 Undo／Redo、重置、儲存場景；提示尚未儲存的變更。成功儲存必須寫到專案的**作者來源檔案**，驗證並重新載入確認，而非僅存在 React state、localStorage 或匯出一份無處消費的 JSON。
8. 一鍵「試駕這段路」，以**與遊戲相同**的追車鏡頭、畫面、車流/交通及路況驗收。測試後可回到同一場景工作室，保留選取與鏡頭角度。

## 3. 初版介面

- **上方**：Stage／章節／目前觀察里程、實景／白模／線框、復原／重做、儲存、試駕。
- **中央**：既有實際渲染世界；自由視角與鏡頭預設；點選物件後出現輪廓（與「街構」單棟綠框同一操作概念）。
- **右側**：依選取種類顯示分頁：**道路表面**（柏油 PBR、粗糙度、修補／裂紋、路肩混合）、**地形／岩岸**（高度／侵蝕資產或局部烘焙材質、地質類型、植被覆蓋）、**森林**（樹種與原型、密度、高度變異、林緣／林下層）、**景點資產**（prefab、位置、方向、比例）、**光影與氣氛**（有限且可回退的局部預設）。
- **下方**：track station 與 HUD 里程**同時顯示並明確標名**、可視範圍、目前套用的來源資料、Triangles／Draw Calls／資源載入狀態、Dirty／Saved、選定攝影機書籤。

不要一開始堆出一百個跟著 three.js property 名字走的滑桿。先做可對應美術行為、實際能保存的少量控制。

## 4. 技術選擇與重要邊界

**現有架構足夠：Three.js + TypeScript + Vite，無須換引擎，也不先引入 Blender 的完整操作框架。**

- 鏡頭：Three.js OrbitControls（旋轉、平移、縮放）；需要時加自由攝影機與沿路導覽。
- 選取：Raycaster + 穩定 object ID；單棟／單棵／單個 Scenic Package 選取後加輪廓或 Helper，不能強制把 InstancedMesh 拆成獨立 draw calls。
- 位置編輯：TransformControls（translate／rotate／scale），並提供 roadDistance／lateral／yaw／scale 數值面板。坐標及站點以現有 road sampler 轉換；不能臆測「UI 公尺」一律等於 track station。
- 三視圖：實景用當前素材／光影，白模和線框由檢視層安全替換適當網格的材質；海水、天空、透明特效及 UI Gizmo 應另訂保留策略。**這是觀察模式，不是將 PBR 材質刪掉或全域改材質。**
- Stage：沿用目前的有限道路、Worker chunk、Stage 資料、Ultra Water／風場等既有能力。從同一個場景建構／渲染途徑產生 Studio，**不要複製一個較漂亮但與遊戲不同的展示引擎**。
- 美術工具：Blender、地形侵蝕、掃描岩石、樹木生成器繼續在**離線資產製作端**；Studio 管理已存在的資產變體、組件與實時可編輯參數。複雜山體雕塑與材質烘焙不必在瀏覽器重做。
- **安全：僅本機 Vite dev 可儲存**。透過明確 allowlist 的 Vite middleware：驗證 loopback 來源、同源 Origin、大小／schema／欄位邊界、預期版本或 hash，採安全原子寫入並檢查 schema。不能讓請求指定任意路徑，也不能讓公開 PWA／網路訪客存取作者硬碟。現有 `vite.config.ts` 已有 dev-only capture middleware，可參照其安全策略而不是擴充為任意檔案寫入。
- 重新生成：若編輯器改動的是可預覽的姿態與材質，立即視覺更新；若需產生資源或 Worker 重建，只重建受影響的範圍或明示重新整理。儲存成功後用原來源重載確認。
- **不自動 Git commit、不自動推 main**；本地寫回 dev 的原始素材，使用者／Codex 依既有流程檢查後 commit。存檔、可玩、藝術通過、Pixel 8 通過、發行是不同狀態。

### 目前資料來源及寫回規則

| 現有資料 | 權威／限制 | Studio 初版 |
| --- | --- | --- |
| `content/stages/coast/road.json` | 正式道路線形、海拔、banking、Worker／物理共用 | **只讀**；可看不能偷偷調行車物理 |
| `content/scenery/packages.json` | 可重用 Scenic Package 成員相對布局 | 針對真正存在的可編輯項目寫回 |
| `content/stages/coast/scenic-layout.json` | Scenic Site anchor、相對位置與參數 | **作者來源**；可修改已載入的 site／prefab |
| `content/stages/coast/scene.json` 與 `direction.json` | 由 scenic build 產出的部分視圖 | **不可直接當作者主檔編輯**；走既有 build/check |
| `content/prefabs/catalog.json` | GLB 型號、來源和授權關聯 | 初版只選已允許的資產，不任意讀本機檔案 |
| `content/stages/coast/effects.json` | 全段現有夕陽、海水、風與效能參數 | 初版只預覽，後續需要**經驗證的局部 override**，不讓調某一站改壞整關 |
| `src/coast-terrain.ts`、`src/coast-nature.ts`、`src/working-harbour-macro.ts` 等 | 一部分地形／岩岸／森林仍是 TS 演算法 | **目前不能宣稱所有參數可編輯**。逐項把真正需要的美術參數抽成受測資料，再提供 Studio 控制 |

**永久設計原則：** 地形、岩岸、森林、道路、物件之所以能在 Studio 內調整，是因為系統真的讀取同一份 Authoring Data，而不是 UI 改了另一個獨立 Demo 的狀態。

## 5. 分段導入，不做大型空殼

### M0：第一條「真的可存檔」的垂直切片

選一段當前已存在的**Working Harbour 岩岸**或 Michael 指定的風之海岸實際站點（不可使用舊 4,600／5,420 m 佔位錨點冒充目前施工位置）。

**最小驗收集合，缺一不稱 MVP：**
- 從 dev 本地進入 Studio，實際看到遊戲同源的道路、海水、岩岸與景觀（不是獨立創作的展示場景）。
- 自由攝影機、沿路定位、實景／白模／線框三模式。
- 至少一個實際存在的 prefab 選取／位置變更，及一個可視化道路表面或岩石／植被美術參數變更；都真的作用於場景。
- Undo／Redo；明確 Dirty／Saved；把變更寫回允許的來源檔，重新載入仍保留，並能在正式遊戲的**相同段落**看到；舊值可以回復。
- 「試駕這段路」連結跳轉正確、可重現；沒有解鎖主線部署、道路物理、AI、既有角色與海水設定。

當前 Working Harbour V4 Macro 已獲 owner 接受，但 Composition 仍受單獨驗收約束；Studio 不代替那個美術驗收，也不在此要求改動既有路線。風之海岸之新站點以最新 Stage 資料為準。

### M1：自然景觀與道路 LookDev

- 柏油材質：PBR baseColor／normal／roughness／裂紋／磨耗／路肩材質過渡。
- 岩岸：離線掃描／建模的岩石 Prefab、地質材質變體、濕乾過渡、局部可重建輪廓。
- 森林：樹種／原型套件、林冠／中層／灌木／地表四層、密度／高度／風動、保護行車視線與路緣空間。
- 近山：高度圖／侵蝕／坡度／土壤／植被遮罩與 chunk 接縫，對接正式道路與海水。
- 天氣／光影：保留共享日照和全球風場，局部外觀 override 需過場轉換規格，不能簡單以每段不同太陽角度製造跳變。

### M2：整關作者效率與發行效能

- 章節列表、材質／景點 Preset、複製配置、區段差異、版本 A/B 和相機書籤。
- 分段資源開銷（tris/draws/texture/upload/CPU/GPU）、PC LookDev 與 Pixel 8 獨立量測、縮減 LOD 且保持原始品質樣品。
- 已確認美術資產依 Asset Library → Scenic Package → Stage Layout 移動／重用；大型地形只做適配，不重新建模。

## 6. 明確不做

- 不 Fork Three.js Editor、不引進整套 Unity／Unreal、不把遊戲改成 React/R3F 或另一個渲染器。
- 不把 30 km 公路一次性載成單一巨大 GLB，或讓地形美術檔控制車輛碰撞。
- 不在初版做瀏覽器版 Blender（雕刻、節點編輯、貼圖烘焙、重拓樸）。
- 不做只有鏡頭＋假滑桿＋Export JSON 的漂亮空殼。
- 不將 Studio 暴露在 `main`／公開 PWA 的一般玩家選單，不做無授權的雲端存檔。
- 不在 Studio 的第一輪推倒已驗收海灘、港口 Macro、主角車或獨立演算法。

## 7. 驗收證據

M0 完成需交：可開啟的 dev Studio、同一區段的三模式截圖、選取前後的場景畫面、**儲存→重新整理→同段試駕**錄影或等效實際瀏覽證據、來源 diff／測試記錄、Undo/Redo 驗證、無變更的正常遊戲回歸。任何未執行的本地／手機驗收都標記 UNKNOWN。
