# v0.2 acceptance — Driving Is a Game + Pixel 8

**Hard rule:** A build or 90-second auto-rail ride does not demonstrate OutRun gameplay. Test the physical consequence of **not steering** through the same bends a player can navigate.

Every item gets **PASS**, **FAIL** or **UNVERIFIED**, with evidence. Do not equate desktop phone emulation with a physical Pixel 8.

## Paired driving regression (must automate)

For left and right bends, use the **same deterministic starting state** (position, heading, speed, throttle and road segment).

1. **A — No steer:** input steering=0. Road heading changes but car does not magically match it. Relative lateral distance increases, footprint crosses asphalt edge and offRoad becomes true.
2. **B — Human steering:** apply deliberately selected steering inputs along the bend; car remains on road at a reasonable speed. The test may use an externally scripted driver, **not hidden gameplay auto-steering**.
3. **C — Recovery:** start off-road, steer onto asphalt, verify penalty ends without positional snap or forced reset.

Trace simulated time, curve direction/curvature, car heading/error, lateral offset, speed and offRoad. Include an actual rendered-browser test, not only mathematical unit tests. If handling tuning breaks A or B, the milestone fails.

## Camera / road / art review

- Measure FOV and chase offset across low, medium and high speed with equivalent terrain; they do not scale with speed.
- Capture desktop **1280×720** with car prominent, a meaningful bend and clear roadside movement.
- Capture mobile **~960×432** and **844×390** in landscape, both control layouts. Inspect true pixels, not just image file paths.
- Visibly stronger crest, climb, descent; stable road/vehicle contact. Stronger contrast without washed-out scene or oversaturated neon.
- Drift is visible and recoverable; skid audio tied to slip. Audio sound quality is a **human listening** gate unless Codex genuinely auditioned it.

## Physical Pixel 8 validation (do when device is connected)

See `docs/PIXEL8_PLAYTEST.md`; log each separately:
1. Chrome tap-to-start enters genuine fullscreen/landscape or an honest actionable fallback; browser bar absent when fullscreen succeeds.
2. Chrome **installed** PWA launches fullscreen+landscape from home screen (if installation is offered and actually tested).
3. Camera cutout, two landscape orientations, safe areas and gesture regions do not block controls.
4. Two thumbs: gas+steer and brake+steer; layout swap, persistence, finger-release order, no sticky input.
5. Pause, rotate, leave/reopen app, exit/reenter fullscreen; render and input recover.
6. Play 60+ seconds, record real FPS if instrumented (target ≥30 sustained), check heat and input latency.

If device inaccessible: mark all physical checks **UNVERIFIED**. Simulating Pixel CSS dimensions is useful but **not** hardware validation.
