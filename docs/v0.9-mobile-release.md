# v0.9 mobile release blocker

Status: implementation and browser verification complete; **physical Pixel 8
acceptance is pending Michael's test**. No deployment or promotion to `main`.

## Findings and changes

- Startup formerly waited for all six initial road/scenery chunks. `ready` now
  requires a complete neighbourhood from 80 m behind to 1,200 m ahead, including
  scenery. At the standing start this is chunks 0 and 1. The existing 5 km preload
  continues in the background. Worker dispatch and main-thread commits prioritize
  nearby chunks; `fullyReady` retains the whole-window inspection condition.
- Every scenery clearance query scanned the whole route and repeatedly evaluated
  the width profile. A worker-owned spatial grid caches the original segment
  widths and selects nearby segments before applying the same distance predicate.
  It does not alter seeds, placement offsets, density, route geometry or art.
- Tire raycasts were a significant main-thread cost. They now query nearby ranges
  of the original asphalt/shoulder triangles. Temporary query ranges are restored
  immediately; rendering and other inspection raycasts use the complete meshes.
- Coarse-pointer devices use pixel ratio 1 instead of 1.25 (36% fewer render
  pixels), disable the dynamic shadow-map pass while retaining existing car and
  wheel contact shadows, and use a 1,400 m far plane instead of 2,200 m. Fog is
  already opaque at 1,100 m. Desktop rendering settings are unchanged.
- Development-only `?perf=1` shows rolling FPS, navigation-to-nearby-ready time,
  nearby road/scenery states, draw calls, raycast time and render CPU submission
  time. It remains visible in fullscreen and is absent from production builds.
- Both PWA cache writers use `coast-drive-v09-mobile-1`. Previously `main.ts`
  recreated `coast-drive-v085-1` despite the worker using the public-release name.

## Measurements

After: this change. Fresh browser contexts, local Vite development server, Edge,
915 × 412 touch viewport, device scale factor 2.625, CDP 4× main-thread CPU
slowdown. These are **browser-emulated measurements**, not Pixel 8 measurements.
The desktop GPU and worker CPU are not emulations of the phone. Localhost does
not measure mobile download time. Each cold-start figure is one run, not a
statistical latency guarantee.

The after worker initialization measured 243 ms. Farther road preparation remains
up to about 157 ms per chunk; this was not the clearance bottleneck. The retained
late-window profiling history shows main-thread commit p95 of 0.20 ms before and
after, with maximum individual commits of 0.80 ms before and 0.50 ms after. The
existing 3 ms pump budget remains. Upload measurements are CPU submission time,
not asynchronous GPU execution time; there is no measured Pixel GPU time here.

A separate after-only normal simulation used scripted throttle/steering for
15 seconds in each of canyon, city and coast. After two settling seconds, each
world's minimum rolling FPS was 59.98 or higher, and nearby readiness remained
true. This is not a full ten-minute thermal soak or physical touch/controller test.

## Empty-roadside investigation

Seed 1's full 70-chunk audit produced 426–2,031 scenery instances in every chunk.
Only 4 of 5,203 clearance queries rejected a placement. The indexed predicate was
also compared against the original full-route calculation across thousands of
positions, offsets, widths and clearance radii. The sampled before/after instance
counts are identical, and worker output remains deterministic across generation
order and seeds 1–3.

These results identify expensive scenery generation and queue ordering as the
streaming bottleneck, rather than insufficient density or widespread placement
rejection in the tested route. No culling defect was observed in the three-world
visual checks. The exact Pixel symptom still needs confirmation on the device.

Scripted 100 m jumps every 250 ms tested chunk crossings in all three worlds at
up to 400 m/s. All 45 sampled nearby windows had road and scenery ready, nonempty
scenery and tire gaps below 0.1 m. This is a streaming stress test, not a handling
simulation. [Audit](evidence/v0.9-mobile/scenery-audit.json) and
[streaming results](evidence/v0.9-mobile/streaming.json).

Screenshots were visually checked: [canyon](evidence/v0.9-mobile/canyon.png),
[city](evidence/v0.9-mobile/city.png), [coast](evidence/v0.9-mobile/coast.png).
