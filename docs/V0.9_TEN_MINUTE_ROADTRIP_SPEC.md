# v0.9 — 10-Minute Road Trip (first full-length seeded journey)

**ACTIVE USER-COMMISSIONED milestone following real-player v0.8.5 streaming approval (29 Oct 2026, Taiwan time).** The owner opened the existing streamed two-minute Stage and **noticed no stutter, abrupt pop-in or visible interruption**, and confirmed photo capture works. This is a **subjective human GO** to try the long course; it is NOT proof of physical Pixel 8 FPS, bounded GPU memory for a full long route or general all-seed performance. Codex reported v0.8.5 local implementation `97cff65` and handoff `f160929`, clean on `codex/v0.8.5-scene-streaming`. Confirm actual current local source.

**PRODUCT TARGET:** a naturally unfolding, genuinely varied **~10-minute real arcade drive** (typically 8–12 minutes, depending on the human's throttle/brake choices), using existing L1/L2/L3 and the established bounded `SceneStreamer`, with no load screen, visible seam, input hitch or huge initial generation. User must be able to replay the same Seed or choose a new long trip that feels different. **This version adds NEW LONG-FORM PLAYABLE CONTENT, unlike v0.8.5's invisible engine work.**

Documents to reuse: `docs/TEN_MINUTE_ROADTRIP_ARCHITECTURE.md`, `docs/TEN_MINUTE_ROADTRIP_ACCEPTANCE.md`, `docs/V0.8.5_STREAMING_FOUNDATION_SPEC.md`, `docs/V0.8_BIOME_VERTICALITY_METADATA.md`, `docs/V0.8.4_HUMAN_FOLLOWUP_10MIN.md`.

## 1 — User-visible experience: a new road-trip mode

- Add a clear separate selection: **`10-Minute Road Trip`**. Start it from a small existing menu entry and support a stable deep link such as `/?trip=10m` (Codex may adapt routing to existing code; document actual final URL). Keep original **Stage 01 ~two-minute mode** untouched, including exact historical Stage Code + seed + human ratings.
- In long mode offer: **Start / Play**, **Replay Same Route**, **New Route**, visible **Trip Code** (seed + routePlanVersion + handling/version identity), compact progress indicator (distance and approximate progress, not a rigid timer), Pause/Resume (existing 1.0s frozen countdown), proper final finish and KEEP/REWORK/REJECT + subjective difficulty + retrospective praise/issues.
- Stage can be started from standstill with six-speed progression. Target drive around **8–12 minutes for a representative active player**, not an imposed wall-clock 600s expiry. A slower player takes longer. Maintain speed-based real distance/height, 1.75× arcade pace, downhill overrun, brakes, bounded offroad and left/right hand/gamepad controls.
- Initial rough route size ~**70,000 game distance units** derived from a recorded owner run (~13,488 units / 114.95s × 600s). It is a *calibration estimate*, not a mandatory length or a claim that coordinate units are physical meters. Record actual game progress and elapsed time during first full end-to-end test and tune from results.
- Normal stage, original L2 Pilot Lab and original eight BRK r2 KEEP routes remain available. No broken previously approved seed geometry or rewrite of human reviews; new Trip Codes get **UNREVIEWED** and their own persistence keys.

## 2 — Full logical plan is allowed, entire 3D world is NOT

**RoutePlan:** a small deterministic, serializable itinerary of L1 curvature/height/width placements, L2 compound driving motifs and L3 biome phases, with cumulative distance anchors, intended emotional/driving beats, seed, version and lightweight world-coordinate prefix/tangent samples if required for continuity. It may be generated at Start cheaply. It must NOT allocate all 70k units of Three.js road triangulation, ground meshes, props or GPU buffers.

**SceneStreamer:** reuse the **actual locally implemented v0.8.5 streamer**. Continue dynamic rolling build/prefetch, ready-ahead priority, disposal/pooled resources behind, frame-budgeted GPU work, deterministic per-chunk randomization and absolute logical `s` for review/telemetry. No second parallel streamer. Adapt chunk-length / lookahead to actual high-speed drive and steep biomes, not arbitrary fixed "six chunks" for every camera orientation.

- The first playable frame has enough critical road/rail/terrain ahead, while no far-future geometry is materialized. For 10 minutes the set of active chunks/GPU geometries/JS buffers stabilizes after warmup.
- CPU numeric generation may use the existing incremental/worker design only as needed, main-thread Three.js scene creation and GPU uploads are budgeted. Don't sneak a synchronous all-acts material/scene rebuild into biome transitions.
- World precision near route end ~70k units: test Float32 camera mesh jitter, wheel-road alignment, absolute screenshot `s` and local retrospective event markers. Implement render-origin rebasing/camera-relative position **only if v0.8.5 did not already solve this / measurements warrant**; the logical route position must not jump or reset.
- Chunks can extend across biome/road segment boundaries. Sample all road geometry from the same source of truth for position/tangent/curvature/elevation/width; seams must not expose holes or sudden shift in markings/shoulders/camera.
- **Do not prebuild 10 minutes of GPU data at startup.** Showing a pre-generated 10-minute route plan is okay and in fact helps seed deterministic replay.

## 3 — L3 makes a trip, not five replays of Stage 01

**North-star emotional cadence:** a convincing journey with departure, open high-speed freedom, a challenging stretch, scenic release, renewed varied driving, and a satisfying finish. Not every phase needs impossible hairpins or an enforced braking event. Exact "number of L1 bricks" is not a hard requirement.

- Reuse the existing three **CITY, COAST and CANYON** world packs. Have **multiple meaningful scenic phases** (roughly 4–7 phases as a first tuning range, subject to actual drive/video) and at least two clear changes in geography. A new seed can choose coherent alternative order/lengths and L3 scenic motifs, within the currently supported biome/terrain constraints; do not require every seed follow identical city→coast→canyon route. Avoid biologically implausible abrupt desert/city color change in a single frame: blend roadside set-dressing over distance and manage distant sky/terrain LOD.
- **L2 challenge core:** compose distinct, localized, human-approved-style multi-placement L1 experiences (curvature sequences, crest/valley, width) with actual variability. Use past KEEP pilot designs as **motifs**, not literal long-playback fixed copies. L2 should **not** include mandatory generic lead-in/out straight; L3 deliberately inserts only useful buffer/accelerate/reveal/braking approach. Avoid the old v0.8 Stage's repeated 800-unit non-curve gaps, and don't simply repeat the identical three pilots five times.
- **Driving variety:** at least some full-throttle sweeper passages around 270–300+, visibly large dramatic but reasonable canyon elevation, technical bends that clearly benefit from earlier braking, S/reverse bend rhythm, generous scenic rests and opportunities to regain sixth gear. Road width: four marked lanes dominant, 6/8 secondary, rare 2/3 purposeful moments; terrain-supported steepest roads relatively more likely in canyon, but coastal cliffs and city hills are allowed.
- The stage as a whole should give multiple meaningful speed decisions but preserve famous arcade high-speed release. The existing player in a 114–117s Stage held GAS ~94% and braked only ~3s; long-form version should introduce substantially different **patterns of player action**, not require arbitrary exact brake count/road-edge violations. If two automated strategies (careful brake, no brake) behave exactly the same in every technical corner, adjust challenge placement/calibration **without modifying global car physics**.
- **Seed genuinely changes the road the player DRIVES:** curve direction/order/intensity and duration, summit/descents, lane-width schedule, relative scenic reveal and L2 motif sequencing, not just trees/paint. Same `Trip Code` and generator/handling revision replay identical geometry and scenic props regardless of streamer scheduling. Different seeds should feel different but still coherent.
- Existing world looks still have the owner's known v0.8.4 defects (a distant elevated road that reads like a hollow ribbon, trees in too-even sparse rows). **Do not pause 10-minute feature to make photorealistic art.** Preserve existing baseline and ensure NEW generated long-route sections have **no catastrophic new unsupported road void**; substantial foliage, bridge/terrain/city depth rework is a separate v0.9.1 visual milestone, following human long-drive approval.

## 4 — Ready-to-play pacing, not a giant procedural planner

- Define a SMALL readable `TripRecipe`/`ExperienceSchedule` list with stages of player-experience intent (`sweeper / crest reveal / canyon technical / coast cruise / S rhythm / recovery`). Choose and parameterize already available L1/L2 assets from weighted seed decisions. Do not build a full AAA graph search or automatic difficulty optimizer; simple finite road continuity checks and human review are the quality gate.
- Distinguish HIGH-LEVEL intended rhythms from effective L2/L1 implementation. Each stage beat contains multiple overlapping or sequential L1 placements where useful; L3 can connect them directly with small smooth blend and only occasional intentional buffers. No invented fixed "must be 9–11 L1 per 37s".
- Route construction must be deterministic and fast. If source needs preview, a text-level `Route Map` of upcoming world segments and drive intent is enough; **no new standalone Stage Editor UI**.
- New route metadata should expose enough structure for Julia/user to analyze: absolute `s` boundaries, biome, C/E/W profile IDs, core/buffer role, expected steering demand at reference speed, nominal acceleration/recovery intent. Do not add an intrusive debug HUD for normal driving.

Ensure memory remains bounded enough for a 10-min run, export at finish, and do not write the whole capture history into browser localStorage every frame. User initiates exports; no automatic data upload.
- If photos use the dev-only Windows `captures/YYYY-MM-DD` path, preserve unobtrusive saved toast and correct local-PC pause menu Open Folder. No new photo gallery.
