前三組在 Three.js 中以同一個乘客建構流程指定 portrait 精度，抽出實際乘客置於灰色背景，用固定棚燈及垂直 25° 視角拍攝。正面、左前 45°、右側 90° 相機到臉部原點的水平距離均為 1.18 m。正面兩張的表情權重分別為 0、0.58；45° 為 1。正側面保留頭髮自然遮住遠眼的輪廓。

後兩組使用預設 driving 精度和遊戲既有黃昏光照。桌面 Chrome，1600 × 900，`?at=3210&r5qa=1&trafficSeed=42`。座艙照沿用 H0 橫向 −1.75 m、停車煞住 1.1 s，車體局部眼點 (0.85, 2.25, 2.05)，瞄準 (0, 1.24, −0.40)。追車照由 3210 m、橫向 0、初速 63 m/s 開始，沿同一輸入逐幀過彎，用預設追車相機拍攝。

## 模型與動作

- [臉部幾何](../../../src/passenger-face.ts) 共用頭顱截面、顴骨、眼眶、鼻樑和下巴曲面。眼球可見區、眼瞼、虹膜和唇部沿各自的三維曲面生成，合用一個索引網格與頂點色材質。一個表情變形權重同時帶動嘴角、唇縫與臉頰。
- [髮型](../../../src/hero-groom.ts) 用七束有厚度的額前與側髮銜接偏分髮頂；五組後髮沿用根部、髮尾的兩段風動與實例化。兩套精度採用同一組髮束控制點，競速時只建立低密度網格。
- [車內整合](../../../src/car.ts) 保留敞篷車上原有的乘客頭部樞紐、座位、0.84 倍縮放與白色無袖洋裝。[動作](../../../src/occupants.ts) 將日常微笑連到既有揮手與歡呼的時間軸，動作結束回到平常表情。兩種精度可用同一個頭部接到未來的人物展示，遊戲現在仍然同步建立上半身。
- 造型與幾何由本專案直接編寫。表面顏色、眼睛亮點和髮色使用幾何及頂點色；競速場景沒有新增人物燈光或透明髮層。

## 實測成本

同一工作站、RTX 5070 Ti、Chrome WebGL，對照改動前 `5acc5f8`。頭部統計包含實際提交的五組髮根和五組髮尾實例。

| 駕駛版指標 | H0 | H1a |
| --- | ---: | ---: |
| 女乘客頭部與頭髮三角形 | 2,144 | 3,060 |
| 頭部主畫面繪製次數／材質數／幾何數 | 5／5／5 | 4／4／4 |
| 頭部幾何屬性、索引及 morph 陣列合計 | 124,056 B | 98,508 B |
| 3501.20 m 全場主畫面繪製次數／三角形 | 534／928,188 | 533／929,104 |
| 3501.20 m 全場 renderer 記錄的紋理數 | 59 | 60 |
| 固定追車畫面重繪耗時，中位數／P95 | 3.2／3.6 ms | 3.5／4.1 ms |

高密度特寫頭部共 21,000 個三角形，平常開車只載入 3,060 個。既有整車幾何預算檢查採每個網格計一次的口徑，駕駛版為 13,822，通過原訂小於 14,000 的上限。WebGL 的表情 morph 需要額外的 GPU 資源；上表的位元組數只涵蓋幾何陣列。

重繪量測在已行駛至指定位置後固定模擬，先暖機 8 次、量測 48 次，以同步讀回一個像素等待主畫面繪製完成。這包含桌面 CPU 提交與 GPU 等待，無法據此判定手機整場的幀率。工作站未偵測到 Pixel 8，手機實際移動幀時間和髮尾的小螢幕辨識度仍待驗收。

本地 `npm run verify:dev` 通過，包含建置、場景檢查與 110 個測試檔的 489 項單元測試。新增表情回歸檢查涵蓋兩種精度的揮手與重置；既有座艙空間、頭髮風動、歡呼和整車幾何預算檢查均通過。下一步由 Julia 與使用者決定臉型、笑容及髮束的美術驗收結果。
