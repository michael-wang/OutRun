# v0.3 Arcade Velocity — acceptance

## Assessment levels

- **P0 = release blocking** for v0.3 handoff; fix rather than paper over.
- **P1 = important next-level gameplay**; expected if P0 is met, but report any deficit honestly.
- **P2 scenic themes = BONUS**, not a handoff condition.

Use **PASS / FAIL / UNVERIFIED** with real evidence. No claim that synthetic tests prove subjective fun; human playtest still needed.

## P0 — Framing and HUD

| ID | Check | Evidence |
| --- | --- | --- |
| FRAME-01 | Car onscreen width targets ~20–25% landscape Pixel-like 20:9, ~20–26% desktop 16:9, without clipping | Actual game screenshots at Pixel-like 960×432 (or measured actual CSS size) and desktop 1280×720; numeric projection/bounding rect if available |
| FRAME-02 | Car placed lower (rear/bottom ~88–95% viewport height) with enough forward road to see turns; road/car do not feel miniature/disproportionate | Visual screenshot review at rest AND in moving curves |
| FRAME-03 | Camera FOV and base chase distance unchanged as speed rises; no speed-driven zoom | Assert camera values at stop/cruise/fast, manual review |
| FRAME-04 | Pixel top HUD no longer dominates; menu actions accessible from compact Pause/Menu overlay, speed readable, left/right driving controls ≥56 CSS px and safe areas respected | Default + swapped Pixel-like screenshot, DOM pointer tests, pause/settings navigation |
| FRAME-05 | Vehicle stays visible and useful on left/right bends, crest and drift, never obscures essential near-turn look-ahead | Actual browser driving capture |

**Reference composition:** Pixel v0.2.1 car ~12% frame width vs OutRun 2 supplied screenshot ~25% at normalized width. These are approximations, not a test to force identical 3D assets or reproduce protected UI.

| ID | Check | Evidence |
| --- | --- | --- |
| SPEED-01 | In-world distance covered and roadside-pass/road-marking motion rise clearly from low to high real in-game speed; HUD not artificially inflated | Deterministic telemetry at 60/120/200-style displayed units or suitable available values, with traveled distance over equal simulated durations |

**Important:** No speed-based FOV, camera-distance change, excessive shake, full-screen motion blur, or cosmetic HUD changes as substitutes for true visual flow.

## Regression must all pass

1. Existing v0.2.1 tests: build, unit, Playwright, mobile two-thumb control (independent pointer IDs, long GAS holds, blur release, swapping and persistence), fullscreen/portrait fallback and PWA manifest.
2. Steering remains player-controlled. At speed, hands-off on left/right meaningful bends leaves asphalt; cannot auto-follow or auto-center.
3. The bounded road corridor still works: off-road penalty, no cross-country/ocean travel, no spin-in-place at outer limit, forward racing progress, inward-steer recovery on both sides.
4. High-speed corner input remains playable and recoverable. Difficulty from road geometry and driving choices, not jittery steering.
5. Renderer adapts to window/fullscreen/orientation changes; don't hardcode phone physical pixels.

## P1 — Road-driving skill

- [ ] Across one ~60–90s normal driving segment, repeated bends include a left-right S, a tighter turn and a visible crest/descent with a curve.
- [ ] A high-speed player holding GAS through a challenging corner can lose speed by going offroad; braking/steering correctly gives a better outcome.
- [ ] Curves remain visually readable with new camera. No unnatural abrupt turns/holes at any sampled speed.
- [ ] Do not trade off responsive steering or the bounded shoulder to make scenes look faster.

## P2 BONUS

- [ ] **OPTIONAL**: one conspicuous coast-to-another-theme transition after ~30–45 s of normal fast driving, no noticeable stutter. If not done, report as bonus deferred.

## Mandatory handoff evidence

- `docs/V0.3_HANDOFF.md` with exact local commit and commands; test results actually run; P0 PASS/FAIL/UNVERIFIED and P1/P2 status.
- Screenshots: desktop 1280×720, Pixel-like 960×432, narrower 844×390 where useful, including default and swapped controls, at rest and fast.
- Motion: actual low/high-speed comparison and full acceleration clip. Do not rely on static screenshot alone.
- Quantify frame occupancy with a bounding width fraction **from displayed result**, not from mesh dimensions.
- Human evaluation prompts: **Does the car look big enough? Is forward road readable? Does the speed feel fast? Do corners demand skill?** Pixel real-device fullscreen/FPS/sound checks remain explicit if no hardware connected.
