# v0.1 First Drive — acceptance & self-QA

**Two layers:** Codex must independently verify objective functionality and inspect actual rendered screenshots. The human reviewer later decides whether driving *feels* good and the art is appealing. Automated green checks are necessary, not a substitute for a playtest.

## P0 — Must work before calling the milestone playable

| ID | Acceptance check | Evidence expected |
| --- | --- | --- |
| P0-01 | `npm install` and `npm run build` succeed; `npm run dev` serves a real page | Command logs and local URL |
| P0-02 | Start, pause/resume, restart work; no uncaught app errors | Browser check + error log |
| P0-03 | The car visibly moves forward **only with accelerator**; brake measurably lowers speed; released controls do not stick | Automated/game-state checks + browser run |
| P0-04 | Left and right steering physically affect road-relative position/heading; car and camera remain coherent on bends | Browser drive, screenshots or short recording |
| P0-05 | Road has both turn directions and elevation, is continuous, and supports at least 60 s driving without a missing section | Timed drive / deterministic test |
| P0-06 | Higher-speed cornering creates controllable slip with **audible skid feedback**; audio can be muted | Inspectable slip/audio state + manual/audible browser verification where possible |
| P0-07 | Mobile default: left steering, right **accelerate above brake**; simultaneous touch works | Landscape touch automation + screenshot |
| P0-08 | Swapped controls reverse the hand groups, persist after reload; simultaneous touch still works | Browser interaction and storage test |
| P0-09 | Landscape mobile and desktop layouts show usable, readable controls; no major road/camera clipping | Actual screenshots at both viewport sizes |
| P0-10 | Game runs without private keys, backend, copied SEGA assets, or remote runtime image/model hotlinks | Dependency & asset review |

If an acceptance check cannot be tested with available tools, mark **UNVERIFIED**, not PASS.

## P1 — Quality expected of this first drive

- View has a coherent recognizable **sunlit coast**: horizon, blue sea, sky, road details, scenic depth.
- Car looks intentionally designed (recognizable silhouette and components), not a default box or unshaded prototype.
- Camera shows approaching road curves and produces a convincing sense of speed without disorienting shake.
- Handling does not jitter; drifting is progressive and recoverable rather than a 90-degree instant snap.
- Button hit areas can be pressed by two thumbs without obstructing the central gameplay.
- If audio cannot be sampled automatically, provide an explicit human listening note rather than claiming it was heard.
- UI colors, text, and spacing do not feel like browser defaults pasted over a 3D canvas.

## Minimal automated test cases

**Unit tests / logic tests**
1. Acceleration increases speed from zero; braking decreases speed; speed stays within sane bounds.
2. Steer-left and steer-right change the intended lateral/heading values with the correct sign.
3. When input is released, no input remains latched after blur/cancel.
4. Drift detection turns on under a relevant fast-cornering state and off after recovery.
5. Settings serialize/restore both handedness states.

**Browser tests (Playwright recommended)**
1. Load game, start driving, assert no page errors.
2. Hold accelerator, observe speed increase; add steer; hold brake, observe lower speed.
3. Run drive/test mode across both curved sections and the elevation change; detect absent road or invalid car position if state probes exist.
4. Landscape mobile viewport: hold accelerator pointer while pressing steering pointer using separate pointer IDs; release either without losing the other.
5. Toggle controls layout; assert positions and both functions; reload and verify persistence.
6. Pause/resume, restart, mute/unmute, resize; detect crashes or broken overlays.

Automated state hooks may be development-only (e.g., a read-only test snapshot and a controlled clock/input driver). Keep them small and documented.

## Mandatory visual review

Capture real game screenshots, at a minimum:
- Desktop **1280×720**, car mid-drive on scenic coastal bend.
- Landscape mobile **844×390**, **default** controls visible.
- Landscape mobile **844×390**, **swapped** controls visible.

Inspect each screenshot for these issues, and fix the obvious failures:
- No sea/sky or uninteresting empty background; horizon discontinuity.
- Car too small, wrong angle, ugly placeholder geometry, wheels floating.
- Road mesh gaps, terrain intersecting car, broken shadows.
- Important road view hidden by HUD, controls too tiny, text clipped or blurry.
- Distracting flashing, inappropriate neon color palette, inconsistent art style.

Do not pass the screenshot check merely because an image file exists. **Look at the actual image** when screenshot-viewing tools are available.

## Handoff proof

Create `docs/V0.1_HANDOFF.md` after implementation, containing:
- Current commit/ref and how to start from a fresh clone.
- List of completed/failed/unverified P0 IDs and relevant evidence paths.
- Exact results of build, unit tests, browser tests, and a simple console-error check.
- Desktop/mobile screenshot locations and visual critique, or why capturing them was impossible.
- Known issues ranked by severity.
- Three questions for the human playtest: **Is the scenery appealing? Does speed feel exciting? Is the drift satisfying/controllable?**

Do not report performance numbers, audio listening, or visual checks that were not actually observed. If quality falls short, fix what can be fixed autonomously before handoff.
