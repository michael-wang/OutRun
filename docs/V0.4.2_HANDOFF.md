## Navigation and input

`src/handling.ts` replaces the old yaw/slip navigation with:

```
s += indicatedSpeed * effectivePace * dt
x += (steeringAuthority(speed) * effectiveNotch - curvePressure(curvature, speed)) * dt
```

At straight + neutral, x remains exactly where the player left it. On bends, neutral produces outward drift. There is no lane spring or automatic correction based on x. Yaw/roll/slip are bounded rendering/audio outputs only and never feed either navigation equation. The camera follows the road tangent with the accepted fixed FOV/dolly; the car is positioned on the generated road plus x. This tangent-based presentation is intentional in the new model; it is not the old independent-yaw model. Steering and braking remain necessary to keep x on asphalt.

The ±9.6m outer center limit holds contact without spin and preserves forward progress. Neutral or outward input cannot release contact; inward input must actually produce inward lateral motion. Existing footprint-based asphalt classification and off-road drag remain. Holding enough steering at too high a speed can still fail until the player brakes. Visual attitude is bounded to ±0.28 rad; meaningful imbalance can squeal, ordinary matched notches stay quiet.

`src/steering.ts` has configurable `STEERING_STEPS=4`. Effective levels:

| Left | | | | Neutral | | | | Right |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| -1.00 | -0.75 | -0.50 | -0.25 | 0 | +0.25 | +0.50 | +0.75 | +1.00 |

The raw cursor is continuous. Base center dead zone is 0.08 normalized magnitude, with 0.025 Schmitt hysteresis: first-notch entry at 0.105, return below 0.055; other thresholds are midpoint ±0.025. Release/cancel resets immediately. Unit tests cover 3/4/5-step configurations; browser touch tests cover jitter, deliberate threshold crossings, multiple pointer ownership, cancellation and both hand layouts.

## Gameplay-first calibration and real geometry

`src/challenges.ts` authors desired signed required steering, reference speed, duration, 14m road width, cosine transition and coastal elevation. The course has two identical opposing halves, each containing the five scenarios. At reference pace it takes 76 seconds; the complete test-driver lap took 79.1 seconds. The second half is the same sequence rotated 180°, closing an 8,497.222m loop without a residual-position warp.

At `vRef = 230/3.6 m/s`, authority is 12m/s and grows linearly with indicated speed. Pressure is `gain * curvature * indicatedSpeed²`. Required steering is pressure / authority, so core demand varies linearly with indicated speed. **The 1.75 pace is not squared into pressure.** It scales real longitudinal travel and segment length.

Cosine ramp area is accounted for before constructing geometry: the signed demand-time integral determines one half-turn. This fixes one global `curvaturePerSteer = π / (referenceTravelSpeed * signedDemandSeconds)`. The pressure gain is then `12 / (vRef² * curvaturePerSteer)`. Each segment curvature is its authored demand times that fixed coefficient. `src/track.ts` integrates curvature to heading/centerline, adds a smooth periodic elevation, and `src/world.ts` sweeps the actual road/shoulders/markings. No arbitrary spline was labelled after construction; there is no runtime difficulty adaptation.

| Scenario | First-half distance | Core curvature (1/m) | Need at 230 | Need at 190 | Intended action |
| --- | --- | --- | --- | --- | --- |
| Low left | 447–1006m | -0.00062720 | -0.25 | -0.2065 | One notch left |
| Medium right | 1118–1677m | +0.00125441 | +0.50 | +0.4130 | Two notches right |
| High right | 1789–2348m | +0.00188161 | +0.75 | +0.6196 | Three notches right |
| Extreme right | 2460–3242m | +0.00301058 | +1.20 | +0.9913 | Brake to about 190, full right |
| S left → right | 3354–4070m | -0.00125441 → +0.00125441 | -0.50 → +0.50 | -0.4130 → +0.4130 | Slide through neutral; reverse correction |

Normal bends have 1-second reference ramps and 3-second cores. Extreme has the same ramps and a 5-second core; S lobes have 0.6-second ramps and a 0.4-second straight between them. Brief relief straights provide release opportunities. At speeds other than the reference, discrete rounding can require occasional notch adjustments; there is no hidden centering to conceal this.

## Browser evidence

- [Actual motion review](evidence/v0.4.2/review.html): paired Low/Medium/High clips, paired Extreme clips, continuous S input and long road loop. Challenge clips use trusted CDP touch events, including real GAS/BRAKE contacts; the long loop uses an explicitly external test-only controller. Normal game has no autopilot. Recordings are silent; sound is measured separately.
- [Calibration](evidence/v0.4.2/calibration.json), [complete course traces](evidence/v0.4.2/course-unit.json), [paired browser gameplay](evidence/v0.4.2/paired-gameplay.json), [touch hysteresis](evidence/v0.4.2/hysteresis-touch.json).
- Equal-entry 230 km/h normal-core runs: no steering leaves asphalt in all three; corresponding notches remain on-road. In the live clips, maximum absolute lateral displacement is approximately 0.34m Low, 0.69m Medium and 1.04m High (including real input acquisition delay and acceleration toward 234). Manual-time trusted-input runs are within 0.47m. This is substantially below the usable road margin; exact mathematical cancellation applies at the declared reference speed.
- Same-segment Extreme comparison: both enter at 230 and use full inward lock on the core, with quantized correction following the entry/exit ramps. High-speed run leaves asphalt, reaching about -7.61m; braking during the visible approach stays between about -0.68m and +0.51m for the whole bend. The braked run varies roughly 183–191 km/h after deceleration. Off-road slowdown is preserved in the failed run rather than hidden or reset.
- S-curve: one steering pointer crosses left → neutral → right without lifting; live lateral range about -0.29m to +0.54m, no off-road samples. Browser exit tests release at the straight and verify unchanged x after another 0.5 seconds.
