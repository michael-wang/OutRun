## Step 1 — Deterministic logical RoutePlan versus materialized SceneChunks

Separate:
- `RoutePlan`: cheap, immutable list of L1 curvature/elevation/width placements, L2 challenge cores, L3 biome phase transitions, seed and prefix/boundary poses/length; a logical ~70k-unit itinerary is allowed up front later.
- `SceneChunk`: a bounded interval indexed by `routeRevision + seed + chunkIndex`. Owns local road mesh, lane marks, edge/shoulder/support geometry, near props, registered scene objects and release handles. MAY refer to shared materials, tree/building/rock templates and skyline layers.
- `SceneStreamer`: tracks player's absolute route-progress `s`, camera look-ahead/curve view, speed and forward travel, arranges lazy build/cache/disposal.

Initial tunable range: chunk length **800–1,000 game-distance units** (NOT world meters; test actual coordinate semantics), initial safe ahead window ~4,000–6,000 units and ~800–1,500 behind. These are **starting suggestions**, not rigid targets. Choose based on actual measured generation latency and camera visibility at current `1.75×` arcade world pace. Full-detail near-road can be a smaller window than coarse visible distant silhouette/terrain LOD. Do NOT generate 10 minutes of meshes upfront under the excuse of "prefetch."

Chunk lifecycle with explicit priorities:
`planned → preparing → CPU-ready → GPU-ready → active/visible → retiring → disposed-or-pooled`.
A chunk is never relied upon for gameplay or displayed until its road surface/edge markings/support are ready; optional tree/building decoration may load later within visual safe distance but must NOT pop conspicuously inside the player's current frame. Prefer minimum ready road/safety assets over deluxe backgrounds. A previous chunk may be kept behind for brief backward camera/glancing turns, then released after a grace distance.

**Critical:** on every chunk boundary, road centerline/heading/curvature and vertical height/grade/width evaluation remain based on the SAME `sampleRoad(s)`, not per-chunk floating local integration. Neighbor endpoint mesh vertices and lane-marking phase must agree; no white-line jump, sudden slope yaw, double overlap or road void. Roads may loop spatially and remain visible at separated `s` ranges: inspect near-camera world-space visibility as well as route-progress s.

## Step 2 — Deadline-safe CPU generation and bounded main-thread GPU work

The render/input RAF must not do unbounded creation or disposal of a whole scene chunk in one pass. Prefer source-compatible incremental generation if profiling proves it sufficiently small. If CPU calculations block frames, add ONE minimal deterministic Web Worker to prepare numeric vertex/index/UV/prop-placement buffers; transfer `ArrayBuffer` ownership instead of copying huge typed arrays. Do not try to create Three.js WebGLRenderer or upload GPU data inside this worker. GPU buffer creation/material shader prep still happens on main thread and must be spread across frames, prioritizing road safety visibility.

No background promises that are purely aspirational: instrument `cpuPrepareMs`, `gpuCommitMs`, queue length, stalled frame time, ready-distance vs player visible-distance, discarded/spent chunks, and resource counts. Start with ~2–4ms MAIN THREAD chunk-commit budget per frame as a hypothesis; tune based on real browser frame-time targets and screen hardware. Do not allocate a new material per instance or compile a huge new shader at the world transition; warm shared base material/geometry templates.

Determinism must be independent of worker completion sequence: derive scenery randomization from seed + absolute chunk ID + feature ID; no mutable global random calls whose outcomes depend on generation order. When route restarts/new seed, cancel obsolete work and do not attach old chunks after reset.

## Step 3 — GPU/resource lifecycle, very long route safety

Chunk-specific BufferGeometry / instanced mesh data must have clear release/dispose logic. Shared material, texture and template geometry must be retained/referenced, **not** disposed when retiring one chunk. Three.js removing Mesh from scene does NOT automatically release its GPU buffers. Use `renderer.info.memory.geometries/textures`, draw calls, chunk counts and browser heap sampling when available; report warmup versus 5/10/20 min simulated journey and repeated start/replay/new seed.

At later 70k coordinate distances, large world-space Float32 values may cause visible jitter; implement camera-relative transforms or a **floating-origin** approach ONLY if actually needed after probing high route progress in a simulated long run. Logical world/s position and screenshot metadata/retrospective feedback must remain absolute, precise and independent from render-local rebasing.

No unlimited cache, infinite behind chunks, network downloads, server streaming or cloud storage. Recycle/dispose; on low-power device drop FAR decorative density and LOD first, never critical road or input responsiveness.
