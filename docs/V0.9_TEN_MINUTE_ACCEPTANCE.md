### Recommended benchmark method (non-product extra UI)

- Use existing v0.8.5 instrumented streamer. In browser complete **three** full long drives, one at actual real-time pace (for hitch data), and drive other seeds in browser with real render updates. A test-clock simulation is okay for long memory soak, NOT proof of 60fps in real time.
- Five RoutePlan outputs compare both geometry and L3 scenery/phase order. Provide human-readable event lists with non-trivial change in curvature sign/duration and technical vs scenic driving; no code metric can prove variety alone.
- Speed profile includes actual standing 0–300 six-speed acceleration and occasional slower corners. Does not fake a ten-minute course by adding pauses or slowing the game timer.
- At 2, 5, 8, 10 minutes, capture GPU memory and forward-ready distance and at least one screenshot immediately before/after geography transition. Don't blame baseline art imperfections for a genuinely new blank stretch.
- Do **not** overbuild new offroad, traffic/collisions, passenger animations or a new terrain engine. v0.9.1 is separate, after owner long-form review.

### Stop gate

If initial stage builds all future meshes, road disappears in fast bend, L3 transitions hitch in actual browser, geometry or player feedback coordinates break beyond 13k s, or memory count increases indefinitely, this is **FAIL** even if tests compile. Fix serious issues before handing to owner. Handoff after actual Codex implementation, then **STOP for at least two owner-played long Trip Codes** to evaluate pacing, flow, physical Pixel performance and desire to replay. **No push, merge, deploy, Stage 02, v0.9.1 visual work, new biomes/traffic or RPG without separate owner authorization**.
