# v0.9 release and arcade speedometer review

## Approved release

`main` was merged and pushed as `dbee2ab761124e859270fd9ed4deb053dd6d965e`.
Its parents preserve the prior `main` and approved `dev` histories. The only
conflict was `.gitignore` ordering; both `.vite/` and `*.webm` remain ignored.
The resulting tree is exactly the approved `7bc690a` tree
(`5accaff57489f77230a8625674b2e0ee8895a67b`). No HUD changes were included.

Release verification: production build, 100 unit tests and 14 Edge browser tests
passed, covering default Road Trip, seeded routes, historical modes, replay,
reviews, telemetry isolation and offline startup. The pushed remote SHA was
verified. Netlify deployment URL/status was not independently verified.

## HUD candidate — dev only

The existing SVG/HTML instrument now has a dark navy face, thick cyan markings,
orange/red high-speed zones, a speed-sensitive rim, a large amber readout and
an integrated G1–G6 indicator. The 0–360 km/h needle calculation is unchanged.
The written visual brief was used; no reference image attachment was available
in the supplied chat context. No optional RPM feature was added.

Historical `#speed`, `#gear` and `#status` CSS overrides were consolidated into
one dashboard block with responsive variants. No dependency, render loop,
WebGL geometry, physics, input, route, telemetry or storage changes were made.
`main.ts` only adds a speed-band attribute update when the band changes.

| Viewport | Gauge size | Digital speed |
| --- | ---: | ---: |
| 844 × 390 | 148 px | 44 px |
| 960 × 432 | 164 px | 44 px |
| 1280 × 720 | 200 px | 54 px |
| 667 × 375 / 568 × 320 | 120 px | 36 px |

The target mobile layouts keep the gauge left of the car and above the steering
area. Smaller landscapes use a compact upper-left placement to clear both car
and controls. Safe-area offsets and `pointer-events: none` remain in place.

## Verification

- Production build passed; only the existing Vite bundle-size advisory remains.
- All 100 unit tests passed.
- 27 distinct Edge browser tests passed across `v09-arcade-hud`, `v041`,
  `v07d-hud`, `v09-mobile-perf` and `v09-public`.

## Performance

Compared with the archived approved mobile baseline, the same Edge probe
(915 × 412 touch viewport, DPR 2.625, 4× main-thread CPU slowdown) stayed at
approximately 60 FPS in all three fixed views. Render CPU submission was
2.10 / 2.81 / 2.88 ms before and 1.83 / 2.85 / 2.73 ms after. WebGL draw counts
were unchanged at 112 / 176 / 185. No meaningful regression was observed in
this probe; it uses a desktop GPU and does not establish phone performance.
The before measurement is copied from the earlier `7bc690a` evidence, not a
new physical-device run. Historical evidence remains untouched.
